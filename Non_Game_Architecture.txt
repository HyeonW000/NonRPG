## 1. 개요 및 월드 레벨 디자인 원칙
* 장르 및 목표 [확정 v3.14]: 조선풍 다크 판타지 + 한국 설화 1~4인 협동 패키지 액션 RPG (논타겟팅, 소울라이크 전투). 요괴로 타락한 설화 속 존재(도깨비·구미호·산군·이무기 등)를 토벌하는 여정. 보스 부위 파괴 → 재료 → 제작·강화가 성장 축.
* 레퍼런스: 몬스터헌터(보스 부위 파괴·제작·출시 후 보스 업데이트), 위쳐 3(괴물 토벌 의뢰), 발헤임/엘든링(친구 초대 협동).
* 규모 [확정 방향]: 거점 마을 1 + 구역형 필드(1막 3구역 목표, 구역별 고정 레벨) + 인스턴스 던전. 상세 구역·보스 목록은 NON-DIS-8.
* 개발 순서 [확정]: 버티컬 슬라이스(마을 + 1구역 + 보스 1종으로 의뢰 → 사냥 → 부위 파괴 → 재료 → 제작·강화 → 저장 한 바퀴) 완성 후 4인 테스트 → 구역 확장.
* 설계 프로세스: 버블 다이어그램 -> 2D 구역 지도(4색 레이어) -> 엔진 그레이박싱
* 필드 크기 [확정]: 탈것 기준으로 설계. 수치 [제안 — NON-DIS-8에서 결정]: 구역 한 변 약 1~1.5km, 마을과 구역은 300~600m 길로 연결. 버티컬 슬라이스의 1구역도 처음부터 이 크기로. 넓어지는 만큼 늘리는 것은 길·지형이고 콘텐츠 개수는 그대로. World Partition으로 제작 (NON-DIS-8 Claude 2차)
* 2계층 도로망: 탈것(초속 12~15m) 전용 평탄한 주 가도와 도보 탐험용 험준한 샛길(지름길, 파밍지) 분리
* 밀도와 시야: 탈것 기준 30~40초(400~500m)마다 이벤트/거점 배치(장승, 서낭당, 잔몹 무리, 숨은 상자 등), 랜드마크 삼각 구도 배치, 초크 포인트(협곡)와 비스타(조망 지점) 교차 설계
* 환경 스토리텔링: 고저차(남쪽 낮은 분지 마을 -> 북쪽 높은 산성 보스)와 식생/색감 변화로 위기감과 서사 전달
* 필드 보상: 웨이포인트/부활 지점 활성화, 숨겨진 폐허 및 동굴 보물상자에서 스킬 포인트 비전서(+1pt), 장신구, 강화 재료 파밍
* 월드 구조: 마을(허브) + 필드 + 인스턴스 던전. 마을을 나서면 필드는 파티 단위 세션(리슨 서버)으로 진행 (8장 참고).
* 멀티 진행 규칙 [확정 v3.14] — "세션은 방장, 기록은 각자":
  * 세션 상태(열린 구역·던전, 보스 등장 여부, 붉은 달 켜짐)는 방장 기준. 방장이 초대하면 아직 안 연 구역도 함께 입장 가능 (권장 레벨 경고만 표시).
  * 개인 기록(활성화한 웨이포인트, 처치한 보스, 연 상자·비전서, 완료한 야담 의뢰, 보상·경험치·재료)은 각자 세이브에 저장. 친구 방에서 한 것도 내 기록에 남음.
  * 상자·비전서는 플레이어마다 따로 (개인 루팅과 같은 방식).
  * 붉은 달(상위 난이도) 해금은 1막 보스 전원 처치 기록이 있어야 함.

## 2. 캐릭터 로비, 생성 및 뮤터블(Mutable) 커스터마이징 시스템
* 로비 레벨 (L_CharacterLobby, Standalone) 초기 진입:
  * 게임 실행 시 SaveGameSubsystem이 슬롯(SaveSlot_01~05)을 스캔. (저장 구조는 8장)
  * 생성된 캐릭터가 있으면 로비 배경(모닥불/사당)에 해당 캐릭터가 현재 착용 장비를 입은 채 대기하며, 빈 슬롯은 [+ 캐릭터 생성] 버튼으로 표시 (캐릭터가 전혀 없을 시 중앙 생성 버튼 활성화).
* 캐릭터 생성 및 프리뷰 흐름:
  1. [+ 캐릭터 생성] 클릭 시 카메라가 생성 단상으로 이동(SetViewTargetWithBlend).
  2. 성별(남/여) 및 6종 클래스 선택: 클래스 선택 시 해당 직업의 고급 시그니처 갑옷과 무기를 착용한 프리뷰 모습으로 즉시 전환 및 전용 포즈 몽타주 재생 (실제 게임 시작 시에는 초보자 기본 장비 지급).
  3. 클래스 설명 및 스킬 프리뷰 영상: UI 패널에 클래스 설명과 대표 스킬 아이콘을 표시하고, 스킬 선택 시 Media Framework(UFileMediaSource + UMediaPlayer)로 Content/Movies/Skills/ 경로의 시연 영상(.mp4/.bk2)을 위젯 내 재생.
* 뮤터블(Mutable / Customizable Object) 기반 의상 및 외형:
  * 방어구 5부위(투구, 상의, 하의, 장갑, 신발) 파츠 교체 시 클리핑 자동 제거 및 스켈레탈 메쉬·텍스처 병합(Merge)으로 드로우콜 최적화.
  * 캐릭터 메쉬 구조 [확정]:
    * 모든 플레이어 캐릭터(6클래스, 남/여)는 **하나의 마스터 스켈레톤(뼈대)**을 공유 → 애니메이션/몽타주를 클래스·성별 구분 없이 재사용.
    * 몸·얼굴·헤어·방어구 5부위는 각각 별도 스켈레탈 메쉬 파츠로 제작하고, Mutable이 런타임에 **캐릭터당 1개의 스켈레탈 메쉬로 병합**.
    * 무기와 방패는 병합하지 않고 별도 메쉬로 소켓에 부착 (발도/납도 시 소켓 이동 — 3.7).
    * 남/여 체형 차이는 같은 뼈대 안에서 메쉬로 표현. 체형 차이가 커서 모션이 어긋나면 성별별 보정 포즈(Pose Asset) 또는 IK Retargeter로 보완 [제안].
  * 외형 구조체(FCharacterAppearanceData): TMap<FName, int32> IntParams(성별, 프리셋 얼굴/헤어, 의상 ID) + TMap<FName, float> FloatParams(추후 얼굴 슬라이더 확장용)로 세이브 호환성 확보.

## 3. 클래스 체계 (1막 4종)
* 1막 출시 [확정 v3.14]: 디펜더·버서커·소서러·클레릭 4종 (탱·근접·원거리·힐). 어쌔신은 출시 후 무료 업데이트 후보, 아처는 2막 후보. 아래 표의 어쌔신·아처 설계는 보관용.
* 인게임 표시명은 조선풍으로 바꾸는 방향 논의 중 (NON-DIS-10). 내부 ID(EJobClass, 스킬 ID)는 그대로.
* 핵심 규칙: 클래스 고정. 클래스 전용 스킬만 학습 가능 (타 클래스 스킬 학습 불가).
* 스킬 상세(쿨타임, 소모량, 계수, 범위, CC, 어그로 배율, 레벨 성장)는 `Skill_Spec.md`에서 관리.

| 클래스 | 역할 | 스킬 발동 무기 (RequiredWeaponTags) | 주 자원 | 주 공격 타입 | 상태 |
|---|---|---|---|---|---|
| 디펜더 (Defender) | 탱커 | Weapon.Type.Sword + Weapon.Type.Shield | 스태미나 | 물리 | 설계 진행 |
| 버서커 (Berserker) | 근접 딜러 | Weapon.Type.GreatSword | 스태미나 (일부 체력) | 물리 | 설계 진행 |
| 어쌔신 (Assassin) | 근접 딜러 | Weapon.Type.Dagger (쌍검/단검) | 스태미나 | 물리 | **출시 후 업데이트 후보** |
| 소서러 (Sorcerer) | 원거리 딜러 | Weapon.Type.Staff | 마나 | 마법 | 자가 회복 보류 |
| 아처 (Archer) | 원거리 딜러 | Weapon.Type.Bow / Crossbow | 스태미나 | 물리 | **2막 후보** |
| 클레릭 (Cleric) | 힐러/지원 | Weapon.Type.Mace (한손 둔기, +Shield 선택) 또는 Weapon.Type.Staff [확정] | 마나 | 마법 (평타는 물리) | 설계 진행 |

### 3.1 자원 소모 규칙 [확정]
* 클래스마다 "주 자원"은 있으나, 소모 자원은 **스킬 단위**로 지정한다 (Skill_Spec의 CostType: Stamina / Mana / Health).
* 체력(Health) 소모 스킬은 HP를 1 미만으로 내리지 않는다 (자기 소모로 사망 불가).
* GAS 구현: 스킬별 Cost GameplayEffect로 처리. HUD는 3대 자원(HP/MP/스태미나)을 항상 모두 표시.

### 3.2 무기 착용 및 스킬 발동 규칙 [확정]
* 무기는 **클래스와 상관없이 자유 착용**.
* 모든 무기에 무기 타입 태그 부여 (Weapon.Type.*). 장착 시 캐릭터 ASC에 해당 태그가 부여됨.
* 클래스 스킬은 각자 RequiredWeaponTags를 가지며, 조건 무기를 들지 않으면:
  * 퀵슬롯/스킬창 아이콘 회색 처리 + 툴팁에 "필요 무기: ○○" 표시
  * 입력해도 발동하지 않음 (ActivationRequiredTags 불충족)
  * 긴급 회피기(ComboBreaker)도 클래스 스킬로 취급 → 조건 무기 미착용 시 회색·사용 불가.
  * 무기와 무관하게 사용 가능: 평타(Ability.Common.Combo), 회피(Dodge), 가드(Block). 평타·가드 몽타주는 착용 무기 타입 기준으로 선택.
  * 패링(Parry)은 **방패 착용 시에만** 가능 (클래스 무관, 5장 16). 방패가 없으면 일반 가드만 된다.
  * 양손 무기/지팡이는 보조 슬롯(방패)과 동시 착용 불가 (장착 시 반대쪽 자동 해제, 기존 구현). 따라서 대검(버서커)·지팡이(소서러/클레릭)로 스킬을 쓰는 동안에는 패링이 없다.
* 무기 교체 규칙 [변경 2026-11-26]: 전투 중에도 인벤토리로 장비 교체·해제 가능 (이전: 비전투 상태에서만). 빠른 교체 키는 없음.
  * 평타 콤보·스킬 도중 교체: 인벤토리에서 더블클릭하는 사이 콤보 입력 시간이 지나 자연히 끊김. 연계 스킬은 시간 제한이 있고, 스킬 발동 시 클래스 무기를 검사하므로 별도 처리 없음.
  * 캐스팅 도중 교체 [확정, 구현 2026-11-26]: 주무기·보조무기(방패) 슬롯이 바뀌면 진행 중인 캐스팅(일반 캐스팅·지면 지정 캐스팅) 즉시 취소. 이미 발동된 스킬은 유지.
* 애니메이션 범위 규칙: 무기 타입마다 평타/발도/납도/가드/회피 몽타주 세트 1벌 필요. 클래스 스킬 몽타주는 해당 클래스의 발동 무기 기준으로만 제작.
* 클레릭이 둔기/스태프 두 종을 지원할 경우 [제안]: 스킬은 상체 시전 몽타주를 공용으로 쓰고(Layered blend per bone), 평타 몽타주만 무기별로 분리.

### 3.3 방어구 재질 및 마스터리 [확정 방향]
* 방어구 재질 4종(판금/사슬/가죽/로브)은 **클래스와 상관없이 자유 착용**.
* 재질별 고유 특성 [제안]:

| 재질 | 장점 | 단점 |
|---|---|---|
| 판금 (Plate) | 물리 방어 높음 | 회피 스태미나 소모 +20%, 이동속도 소폭↓ |
| 사슬 (Chain) | 물리 방어/마법 저항 균형 | 특출난 장점 없음 |
| 가죽 (Leather) | 회피 스태미나 소모 -15%, 이동속도 소폭↑ | 방어 낮음 |
| 로브 (Robe) | 마법 저항, 마나 재생, 쿨감 | 물리 방어 매우 낮음 |

* 재질 마스터리 패시브: 클래스별 패시브 목록에 포함 (예: 디펜더 [판금 마스터리], 소서러 [로브 마스터리]).
  * 효과 [제안]: 해당 재질 3부위 이상 착용 시 해당 재질의 장점 10% 강화 + 단점 50% 완화.
  * 패시브 슬롯(4칸) 중 1칸을 차지하므로 장착 여부가 빌드 선택이 됨.

### 3.4 클레릭 설계 축 [확정]
  1. 범위 즉시 힐(자신 중심 SphereOverlap) / 지면 지정 장판 힐
  2. 주변 반경(8~12m [제안]) 오라 버프 — 방어 / 스태미나 회복 / 공격 중 1종 토글 유지 [제안]
  3. 정화 및 부활 (궁극기: 반경 범위 파티 부활 + 회복)
  * 솔로 생존을 위해 둔기 평타와 신성 지속 피해 장판으로 최소 딜 보장. 단일 대상 지정 힐은 두지 않음.
  * 힐량은 마법 공격력(MagicPower)에 비례 (기본값 + MagicPower × 계수). 최대 HP 비율로만 계산하지 않는다 — 그래야 무기별 차이가 생김.
  * 발동 무기 2종 [확정]:
    * 지팡이(Staff): MagicPower 높음. 방패 불가 → 후방 힐러.
    * 한손 둔기(Mace) + 방패(선택): 둔기의 MagicPower를 지팡이보다 낮게 설정 (물리 공격력은 별도 조정 없음). 방패로 패링 가능 → 전열 힐러.

### 3.5 전투 중 자가 회복 [확정 규칙]
* 물약이 전투 중 금지되므로 클래스마다 전투 중 사용 가능한 자가 회복/피해 흡수 수단을 최소 1개 보유.
* 디펜더: IronStance 유지 중 막아낸 피해의 일부를 HP로 회복 [제안]
* 버서커 [확정 방향]:
  * [광포화](가칭, Rage): 일정 시간 공격력 증가 + 받는 피해 증가.
  * [평정](가칭, Calm):
    * 광포화 중 사용 → 광포화 즉시 해제 + 최대 HP 10/12/15%(스킬 레벨별) 회복 + 스태미나 회복
    * 광포화 없이 사용 → 스태미나만 회복
    * 광포화를 켜고 끄는 반복 남용 방지: 평정 쿨타임 ≥ 광포화 지속시간 [제안]
  * 패시브 [피의 환희](가칭): 치명타 적중 시 최대 HP 0.5~1% 확정 회복, 내부 쿨타임 1초 [제안]
    (원안 "1% 확률 2~3% 회복"은 체감이 거의 없어 확정형으로 변경 제안)
* 어쌔신 [확정 방향]:
  * 백어택 판정: 대상 정면 벡터와 (대상→공격자) 방향 벡터의 사잇각이 120° 이상이면 후방 [제안]. (내적 1회 계산, 대형 보스는 캡슐 중심 기준)
  * 백어택 적중 시 확정 치명타 + 피해의 일부 흡혈, 흡혈 내부 쿨타임 적용 [제안] (확률형 대신 확정형 권장)
  * 백어택 발생 시 Event.BackAttack 이벤트 송출 (패시브 트리거용)
* 소서러: [얼음 감옥] 무적 중 HP/MP 회복안 — **보류**
* 아처: 클래스 설계 보류
* 클레릭: Heal / Tranquility / SanctuaryOfLife

### 3.6 공통 긴급 회피기 (Ability.Common.ComboBreaker) [확정]
* 다운/연속 피격 경직 등 행동 불능 중에도 시전 가능, 피격을 강제 캔슬하고 제어권 회복. 고유 쿨타임 적용.
* 스킬이므로 클래스 지정 무기 착용 필요 (3.2). 납도 상태에서 사용 시 처리는 3.7 참고.
* 마나 소모: 소서러, 클레릭 / 스태미나 소모: 디펜더, 버서커, 어쌔신, 아처
* 디펜더 [방패 장벽 전개]: 즉시 기상 + 주변 넉백 + 3초 가드 100%
  * 모션 구성 (총 약 1.0초) [제안]:
    * 0.0~0.3초: 쓰러진 자세에서 한쪽 무릎을 짚고 방패를 앞으로 세우며 기상 (State.Invincible)
    * 0.3~0.5초: 방패 하단으로 지면 강타 → 충격파 넉백(State.CrowdControl.Knockback) + 카메라 셰이크 + 먼지 VFX
    * 0.5~1.0초: 가드 대기 자세로 블렌드 아웃, 3초 가드 100% 버프 시작
  * 서 있는 상태(기절 등)용 변형 몽타주: 무릎 짚기 구간 생략, 0.3초부터 시작
* 버서커 [야수의 도약]: 즉시 기상 + 후방 대도약
* 어쌔신 [그림자 소멸]: 잔상을 남기고 공격자 배후로 순간이동
* 소서러 [얼음 감옥]: 자신 빙결 무적 → 해제 시 광역 냉기 폭발 + 넉백
* 아처 [후방 폭발 사격]: 클래스 보류
* 클레릭 [신의 가호]: **보류**

### 3.7 발도/납도 및 전투 행동 사용 규칙 [확정 방향]
* 상태 정의:
  * 납도(State.Weapon.Equipped만 있음): 무기를 등/허리 소켓에 보관. 일반 보행·상호작용·탈것 소환 가능.
  * 발도(State.Weapon.Drawn): 무기를 손 소켓(HandWeaponSocket)에 쥔 전투 태세. 8방향 Strafe 전투 보행.
  * 무기 미장착: 발도 불가. 맨손 평타만 가능 [제안], 스킬 전부 불가.
* 행동별 필요 조건:

| 행동 | 발도 필요 | 클래스 지정 무기 필요 |
|---|---|---|
| 평타 (Combo) | O | X (무기 타입별 평타) |
| 클래스 스킬 | O | O |
| 긴급 회피기 | O (단, 아래 예외) | O |
| 가드 / 패링 | O | X |
| 회피 (Dodge) | X | X |
| 상호작용, 탈것 소환 | X (발도 중 시도 시 자동 납도) | X |

* 발도/납도 조작:
  * 발도·납도 토글 키 (Ability.Common.DrawSheathe). 발도 0.4초 / 납도 0.6초 [제안], 이동하면서 가능(상체 블렌딩).
  * 자동 발도 [확정]: 납도 상태에서 평타/스킬/가드 키 입력 시 **발도 모션만 재생**. 공격/방어는 발도 완료 후 다시 입력해야 실행 (입력 버퍼 없음 — 의도치 않은 공격 방지).
  * 긴급 회피기 예외 [제안]: 다운 중에는 발도 모션을 넣을 수 없으므로, 조건 무기를 착용했다면 납도 상태에서도 사용 가능하며 사용과 동시에 무기가 손으로 이동.
  * 자동 납도: 탈것 탑승, 마을(평화 구역) 진입, NPC/오브젝트 상호작용 시.
* 이동 2단계 [확정] (질주 없음):

| 이동 | 조작 | 속도 [제안] | 스태미나 | 비고 |
|---|---|---|---|---|
| 달리기 (기본) | WASD | 5~5.5m/s (발도 Strafe 4m/s) | 소모 없음 | 기본 이동 |
| 걷기 | 걷기/달리기 토글 키 | 1.8m/s | 소모 없음 | 마을·연출용 |

  * 순간적인 거리 벌리기/접근은 회피(구르기)와 클래스 이동기 스킬(돌진, 점멸, 환영 스텝 등)이 담당.
  * 필드 장거리 이동은 탈것, 던전은 사냥하며 전진하는 구조라 별도 질주 불필요.
  * 발도 중 피격으로 전투에 들어가도 자동 발도는 하지 않음 (플레이어 판단 존중).
* 소켓: 납도 소켓은 무기 타입별로 지정 (DT_ItemData.AttachSocket 사용 — 예: 한손검 pelvis_Socket, 대검 spine_05_Socket, 방패 등 소켓), 발도 시 HandWeaponSocket(방패는 lowerarm_l_Socket)으로 이동.

## 4. 게임플레이 태그 (Gameplay Tags) 완전 명세서
* 원칙: 상태(State)는 "지금 어떤 상태인가", Combat는 "전투 행동 중 무엇을 하는가", Movement는 "이동 제약", Ability는 "어빌리티 식별", Event는 "어빌리티 간 신호", Data는 "SetByCaller 값 키"로 용도를 엄격히 분리한다.
* 중복 금지: 같은 의미의 태그를 두 계층에 두지 않는다 (예: 기절은 State.CrowdControl.Stun 하나만 사용).

### [State.* — 캐릭터 상태]
* State.Dead : 사망 확정 상태 (쓰러짐 유예 종료 또는 부활 지점 선택 전). 모든 입력 차단.
* State.Downed : 쓰러짐 상태(60초 유예). 이동/공격 불가, 부활 팝업 표시, 파티원 부축/힐러 부활/아이템 부활 대상.
* State.Invincible : 무적 (보스 페이즈 전환 연출, 회피 I-Frame, 부활 직후 보호 등). 모든 데미지 무효화 ("무적!" 텍스트 출력).
* State.Groggy : 대경직(그로기). 보스: 그로기 게이지 MAX 시 / 플레이어: 가드 브레이크 시. 이동/스킬 불가.
* State.Stealth : 어쌔신 은신 (적 AI 시야 및 타겟팅 이탈, 어그로 0 초기화).
* State.Mounted : 탈것 탑승. 일반 전투 스킬 차단, 탈것 전용 스킬 활성화.
* State.SafeZone : 탱커 거대 방패 전개 시 등 뒤 부채꼴 안전 구역 내부 (투사체/브레스 차단).
* State.InCombat : 교전 상태. 피격, 공격/스킬 적중, 또는 몬스터가 해당 플레이어를 타깃으로 추적 중일 때 부여·갱신. 마지막 교전 행동(추적 종료 포함) 후 N초 경과 시 해제 (현재 6초. 조정: BP_NonCharacterBase → Class Defaults → Combat → Combat State Duration). 물약·텔레포트·탈것 소환·스킬 초기화 차단 판정에 사용.
* State.Dueling : 마을 내 1:1 결투 진행 중.
* State.Weapon.Equipped : 무기 슬롯에 무기 장착.
* State.Weapon.Drawn : 발도(전투 태세). **모든 평타와 전투 스킬의 ActivationRequiredTags.** 이동 모드가 8방향 Strafe 전투 보행으로 자동 전환.
* State.Defense.Block : 일반 가드. 전방 피해(근접 및 베지어 유도 투사체 포함) 대폭 감소 및 넉백 무시. 제자리 회전(Turn in Place 45°/90°), 저속(40~50%) 8방향 Strafe 허용, 스태미나 자연 회복 초당 4~5% 유지. 스태미나 0 도달 시 가드 브레이크(State.Groggy 1.5초).
* State.Defense.JustGuard : 저스트 패링 성공 판정 구간 (패시브 트리거 / 보스 그로기 게이지 누적).
* State.Evade.Dodging : 회피(구르기/스텝) 중. I-Frame 구간 동안 근접 및 확정 유도 투사체 회피 판정.
* State.Evade.JustDodge : 아슬아슬한 회피 성공 판정 (패시브 트리거).
* State.CrowdControl.* (5대 군중제어 — 부여 시 이동 및 조작 차단):
  * State.CrowdControl.Stun : 기절 (제자리 비틀거림 루프, 이동/공격 전면 차단)
  * State.CrowdControl.Knockback : 넉백 (타격 반대 방향 밀려남 및 넘어짐, 기상까지 조작 불가)
  * State.CrowdControl.Airborne : 에어본 (공중 띄워짐, 착지 및 기상까지 조작 불가)
  * State.CrowdControl.Root : 속박 (하체 고정, 이동만 차단)
  * State.CrowdControl.Freeze : 빙결 (애니메이션 정지 + 얼음 오버레이 머티리얼, 이동/조작 완전 차단)
* State.Phase.One / Two / Three : 보스 페이즈 (보스 전용).
* State.Mode.Ground / Flying / Burrowed : 몬스터 모드 상태 = 몬스터의 "현재 몸 상태(어디서 싸우고 있는가)". 모드별로 사용 가능한 패턴 묶음을 분리.
  * 페이즈와의 차이: 페이즈(State.Phase.*)는 HP 비율로 한 번씩만 넘어가는 진행 단계, 모드는 전투 중 패턴에 따라 수시로 오가는 상태. 둘은 독립적으로 동시에 존재 (예: 2페이즈 + 비행 모드).
  * 예: 날개 달린 보스가 이륙 패턴을 쓰면 Ground → Flying, 착지하면 다시 Ground. 날개 절단(Combat.PartBroken) 시 Flying 진입 불가 → 지상 패턴만 사용. 땅속 잠행 몬스터는 Burrowed 동안 타격 불가.

### [Weapon.* — 무기 타입 (장착 시 ASC에 부여)]
* Weapon.Type.Sword / Shield / GreatSword / Dagger / Staff / Mace / Bow / Crossbow
* Weapon.Hand.OneHanded / TwoHanded (양손 무기 시 보조무기 슬롯 비활성)

### [Combat.* — 전투 행동]
* Combat.Attacking : 평타(1~4타) 스윙 중. WASD 차단(루트 모션 전진만 허용).
* Combat.Casting : 정신집중 시전 중. 스킬 데이터(bCanMoveWhileCasting)에 따라 Movement.Root 또는 Movement.CastWalk 분기.
* Combat.CastingReady : 지면 지정 캐스팅 충전 100% 완료, 좌클릭 즉시 발사 대기.
* Combat.Hit : 일반 피격 리액션(전/후/좌/우). 진행 중 평타/캐스팅 취소, 이동 차단.
* Combat.BlockHit : 가드로 공격을 막아낸 순간의 경직 (0.2~0.3초 이동/회전 잠금, 스태미나 차감).
* Combat.SuperArmor : 피격 경직(Combat.Hit) 무시.
* Combat.ChainReady : 연계 스킬 대기 상태 (2~3초 유예).
* Combat.Immune.CC / Combat.Immune.Damage : CC 면역(보스 상시) / 피해 면역.
* Combat.PartBroken.Head / LeftArm / RightArm / Leg / Tail : 보스 부위 절단 완료.

### [Movement.* — 이동 제약]
* Movement.Root : 이동 입력 완전 차단 (평타, 고정형 스킬, 피격, CC). 루트 모션 이동만 작동.
* Movement.CastWalk : 이동 가능형 스킬 시전. 이동속도 지정 비율(50~70%) 제어, 상·하체 블렌딩(Layered blend per bone).
* Movement.Strafe : 8방향 Strafe 보행 모드 (발도/가드 시 자동).

## 5. 전투, 스탯, 발사 방식, 그로기 및 부위 절단 규칙
1. 공통 3대 자원: 체력(HP), 마나(MP), 스태미나(Stamina).
   * 스태미나 소모: 평타(1타 5~8 / 마지막 강공격 15 [제안]), 회피, 가드 피격(Combat.BlockHit), 스태미나 소모형 스킬.
   * 평상시 N초당 최대치의 15~20% 자연 회복(행동 직후 0.8초 딜레이). 가드 유지 중 초당 4~5%.
   * 가드 피격으로 0 도달 시 가드 브레이크(State.Groggy 1.5초).
2. 공격 스탯 구조 [확정 — v3.4 변경]:
   * 공격 스탯 2종: **물리 공격력(PhysicalAttack) / 마법 공격력(MagicAttack)**. 기본 수치는 **무기**가 부여 (검·대검·단검·활 → 물리 위주, 스태프 → 마법 위주, 둔기 → 물리 + 마법 일부).
   * 스킬마다 피해 타입 태그(Damage.Type.Physical / Magical)를 가지며, 피해 타입에 맞는 공격력을 사용. 평타는 무기의 피해 타입을 따름.
   * 힐량은 마법 공격력에 비례.
   * 방어 스탯 2종: **물리 방어(Defense) / 마법 저항(MagicResist)**.
   * 방어구·악세서리 옵션: "공격력 +N%"(물리/마법 공통 적용) 형태를 기본으로 하고, 고정치 옵션은 드랍 시 캐릭터 클래스의 주 공격 타입으로 생성 [제안].
   * 무기 자유 착용과의 관계: 소서러가 검을 들면 마법 공격력이 거의 없어 별도 제한 없이 비효율이 자연 발생.
   * 데이터 반영: DT_ItemData StatBlock의 AttackPower → PhysicalAttack, MagicPower → MagicAttack으로 이름 정리.
   * 피해 공식 [확정 — 1차]: 최종 피해 = 해당 공격력 × 스킬 계수 × (K / (K + 해당 방어)) × 치명타 배율 × 부위 배율
     * K = 100 (DataTable 상수로 분리, 코드 하드코딩 금지). 방어 100 → 피해 50%, 방어 300 → 피해 25%. 방어가 높아도 피해 0이 되지 않음.
     * 추후 레벨 구간별 K 조정 가능하도록 커브 테이블로 확장 여지 확보.
   * 부위 내구도 차감 규칙: 공격이 **부위 콜리전에 적중한 경우**, 한 번의 타격으로 본체 HP와 해당 부위 내구도가 **같은 피해량만큼 동시에** 차감. 부위 외(몸통) 적중은 본체 HP만 차감.
     * 부위 공략 동기 강화가 필요하면 부위 내구도에만 별도 배율(예: 1.2배) 적용 [제안].
3. 원거리 발사 메커니즘 3종 (ANonProjectileBase & AGameplayAbilityTargetActor_GroundTrace):
   * 유형 A — 논타겟 직선/관통 탄도형 (궁수 관통/폭발 화살, 소서러 화염 화살): 카메라 라인트레이스 목표 지점으로 직선 발사, 보스 부위 정밀 타격 지원.
     * 몬스터 공용: 적 궁수/투척병 등 몬스터 원거리 공격도 같은 ANonProjectileBase 유형 A 사용 (발사 지점 = 몬스터 소켓, 목표 = 발사 시점 플레이어 위치 + 예측 보정 [제안]). 측면 이동으로 회피 가능.
   * 유형 B — 즉발 2차 베지어 곡선 확정 유도형 (소서러 비전 구체, 클레릭 정화의 빛): P0 소켓 / P1 오프셋 / P2 타겟 몸통 실시간 좌표. 보행으로 회피 불가.
     * 파훼: 접촉 순간 State.Evade.Dodging / State.Invincible → 피해 0. State.Defense.Block / JustGuard → 가드 경감 및 패링 패시브 발동.
     * 멀티플레이 동기화 [확정 방향]:
       * 서버가 투사체를 생성하고 P0, P1 오프셋, 대상 액터, 발사 시각, 비행 시간만 복제.
       * 각 클라이언트는 같은 값으로 베지어 곡선을 로컬 계산해 표시 (매 프레임 위치 복제 금지 — 끊김 방지).
       * 명중 판정은 서버에서만 수행. 접촉 시점 대상의 State.Evade.Dodging 등 태그를 서버에서 검사.
       * 지연 보정: 회피 입력 도착 지연을 고려해 서버 판정에 100~150ms 유예 [제안].
   * 유형 C — 지면 마법진 캐스팅 후 좌클릭 발사형 (메테오, 화우의 세례, 생명의 성역): Cast_Start → Cast_Loop(마법진 이동 가능) → 충전 완료 시 Combat.CastingReady + 색상 전환 → 좌클릭 시 Cast_Fire 즉발 (우클릭/회피 시 취소).
4. 피격 리액션 및 CC (플레이어 & 몬스터 공통):
   * 일반 몬스터는 방향별 Combat.Hit 및 5대 CC 리액션 재생, 피격 중 이동 차단.
   * 히트 리액션 규칙 [확정] (모션 팩터 대체):
     * 모든 공격은 히트 리액션 등급 1개를 가짐: None(무반응) / Light(약경직, 움찔) / Heavy(강경직, 크게 젖혀짐). 피격자는 Combat.Hit 부여와 함께 해당 몽타주 재생 (DT_EnemyData의 HitLightMontage / HitHeavyMontage).
     * 넘어짐·띄우기·기절·밀려남·빙결은 히트 리액션이 아니라 **CC 태그(State.CrowdControl.*)**로만 처리 (KnockdownMontage, StunMontage 등).
     * 우선순위: CC 태그 > Heavy > Light. 한 공격에 CC가 있으면 히트 리액션은 무시.
     * 피격자 경직 저항 (HitResist): 0 일반몹 / 1 엘리트 / 2 보스(상시 슈퍼아머).
       * 저항 1: Heavy → Light, Light → None으로 한 단계 약화. CC는 지속시간 50% [제안].
       * 저항 2(보스): 히트 리액션 무시, CC 면역(그로기 게이지로 변환). 대형 몬스터는 강한 타격 시 전용 고통(Pain) 몽타주 사용 [제안].
     * 몽타주 요구량: 히트 리액션은 Light/Heavy × 방향(전/후/좌/우) 세트, CC는 종류별 1세트. 판정 규칙만 단순해질 뿐 몽타주는 모두 필요.
   * 보스는 Combat.Immune.CC + 상시 SuperArmor. 단, CC기 적중은 그로기 게이지 누적으로 변환.
   * CC 대상별 규칙 [확정]:

| 대상 | 규칙 |
|---|---|
| 잡몹 (HitResist 0) | 자유 제어. 다운 중에도 피격 가능. 다운 중 다운 CC를 다시 맞으면 다운 피격 몽타주 재생 후 **다운 시간을 처음부터 다시 계산**. CC 지속시간 감소 규칙 없음 |
| 엘리트 (HitResist 1) | CC 지속시간 50%, 히트 리액션 한 단계 약화. **기상 직후 0.5초 CC 면역** (피해는 정상 적용, 면역 중 흰색 외곽선 표시 [제안]) |
| 보스 (HitResist 2) | CC 면역 (CC 적중은 그로기 게이지로 변환) |
| 플레이어 | **기상 직후 0.5초 무적** [제안] (기상 모션 동안만, 기상 중 공격 불가). 긴급 회피기로 다운 중 즉시 탈출 가능 |

   * 다운 중 재다운 몽타주 [제안]: 누운 상태에서 서서 넘어지는 모션을 다시 재생하면 어색하므로, "누운 채 튕기는(바운스)" 짧은 몽타주를 별도로 둠 (DT_EnemyData에 DownHitMontage 컬럼). 없으면 KnockdownMontage 재생.
   * 다운 중 일반 피격(다운 CC 없는 공격): 피해만 적용, 다운 시간 변화 없음.

5. 보스 그로기 게이지 [확정] (처형기 대체):
   * 보스 HP와 별개의 그로기 게이지 보유. 누적 수단 (Data.GroggyBuildup):
     * 패링 성공 (디펜더 패링 패시브로 누적량 증가 [제안])
     * 저스트 회피 후 회피공격기 적중 (패링보다 적게 [제안])
     * 강공격/차징기 적중
     * 약점 부위 적중
     * CC기 적중 (CC 면역 대신 게이지로 변환)
     * 부위 절단 (대량 누적 + 패턴 봉인)
   * 게이지 MAX 시: State.Groggy 5~7초 + 받는 피해 30% 증가 [제안] → 게이지 초기화 및 다음 필요량 증가(연속 그로기 방지).
   * 일정 시간 비교전 시 게이지 서서히 감소.
   * 클래스별 수단 [확정]: 솔로로도 보스를 그로기시킬 수 있도록 **클래스마다 그로기 누적 스킬 최소 1개** (예: 버서커 강공격, 어쌔신 저스트 회피 반격, 소서러 차징 마법, 클레릭 둔기 강타).
   * 데이터: 누적량은 스킬 데이터(DT_SkillData)의 그로기 누적 값으로 지정. 스킬 툴팁에 "보스 그로기 게이지 증가"를 그 값으로 자동 표시 (설명문에 숫자를 직접 쓰지 않음).
   * [현재 구현] State.Groggy(가드 브레이크용)만 있음. 보스 그로기 게이지는 패링 구현 시 함께 추가.
6. 보스 부위 절단 (UBossPartBreakComponent):
   * 부위별 독립 내구도(Part HP), 해당 부위 콜리전 집중 공격으로 차감.
   * 내구도 0 시 HideBoneByName(BoneName, PBO_Term) 영구 절단 + 콜리전 제거 + 파편 VFX + 그로기 게이지 대량 누적.
   * 패턴 봉인(방식 B): 절단 부위를 쓰는 시그니처 패턴 봉인 또는 대체 패턴 전환. 보스 어빌리티는 실행 전 Combat.PartBroken.* 태그 검사.
   * 상시 약점 배율 없음.
   * 멀티플레이: 절단 상태는 서버 복제 변수 + OnRep으로 처리 (중간 합류 클라이언트 동기화 포함).
7. 보스 페이즈:
   * HP 70% 이하 2페이즈, 35% 이하 3페이즈 [제안]. 진입 시 State.Phase.* 부여, 기존 행동 강제 캔슬, 전환 연출 중 State.Invincible.
8. 조작 방식 및 카메라 [확정] (락온 없음):
   * 키보드·마우스 전용. 락온 기능 없음.
   * 공격 방향: 발도 상태(Strafe)에서 캐릭터는 항상 카메라(마우스) 방향을 바라보며, 평타·스킬은 그 방향으로 나감. 자동 방향 보정 없음 — 플레이어가 직접 조준.
   * 부위 공략: 무기 궤적 판정(5장 14)이므로 플레이어가 위치와 방향을 잡아 원하는 부위를 노림 (예: 꼬리는 후방으로 이동).
   * 원거리 조준: 화면 중앙 조준점 = 카메라 라인트레이스 목표 지점 (유형 A/C 기준점).
   * 카메라 거리: 마우스 휠 업/다운으로 확대·축소. 최소 1.5m / 최대 6m [제안], 대형 보스 대비 최대값은 보스전에서 8~10m까지 허용 [제안].
   * 카메라 충돌: 벽·지형에 막히면 자동으로 당겨짐 (Spring Arm 충돌), 확대 단계는 기억.
9. 이동/회전 제어:
   * 평타 및 고정형 스킬은 Movement.Root(루트 모션만 허용), 이동 가능형 스킬은 상·하체 분리로 8방향 Strafe 허용.
   * 일반 가드는 회전 속도 완화 + 정지 시 Turn in Place + 이동 시 40~50% 저속 Strafe. 탱커 [거대 수호의 방패]는 지면 고정(이동 차단, 회전 극도 제한).
10. 판정 권한 [제안]: 피해/HP/아이템은 서버 권한. I-Frame/저스트 가드는 클라이언트 예측 + 서버 검증(허용 오차 ~150ms).
11. 평타 구조 [확정]:
   * 평타 콤보는 무기 타입별로 다름 (타수·모션·리치는 무기 데이터에서 지정 — 예: 단검 4~5타, 한손검 4타, 대검 3타 [제안]).
   * 콤보의 **마지막 타만 강공격**: HitReaction Heavy, 스태미나 소모와 계수 높음, 그로기 게이지 누적 큼. 별도 강공격 키는 없음.
   * 콤보 데이터: UWeaponDataAsset에 ComboMontages 배열 + 타별 계수/스태미나/HitReaction 지정.
   * 콤보 리셋: 마지막 타 이후 또는 다음 입력이 콤보 구간(ComboWindow)을 놓치면 1타로 복귀.
12. 캔슬 규칙 [확정 + 구간 제안]:
   * 평타 도중 가드, 평타 도중 스킬로 캔슬 가능.
   * 캔슬 가능 시점은 몽타주마다 AnimNotifyState(ANS_CancelWindow)로 지정. 한 번 지정하면 코드 수정 없이 몽타주에서 조정.
     * 기본안 [제안]: 공격 판정 구간이 끝난 뒤(후딜)부터 캔슬 가능, 판정 전(선딜)은 캔슬 불가 → 공격을 누르면 최소한 휘두르기까지는 책임지게 해서 소울라이크 무게감 유지.
     * 캔슬 대상별: 스킬 캔슬 = 판정 직후부터 / 가드 캔슬 = 판정 직후부터 / 회피 캔슬 = 판정 직후부터 [제안].
   * 피격(Combat.Hit)과 CC는 언제든 평타/스킬을 끊음 (5장 4).
13. 선입력 버퍼 [확정 — 필요]:
   * 버퍼가 없으면 콤보 중 조금만 빨리 눌러도 입력이 무시되어 "씹히는" 느낌이 남.
   * 규칙: 공격 중 들어온 평타/스킬/가드/회피 입력 중 **마지막 1개**를 0.25초 [제안] 동안 저장 → 콤보 구간 또는 캔슬 구간이 열리는 순간 실행.
   * 예외: 자동 발도(3.7)에는 버퍼를 적용하지 않음. 피격/CC 중 들어온 입력은 버리고, 긴급 회피기만 즉시 처리.
14. 적중 판정 방식 [확정 방향]:
   * 근접 (플레이어·몬스터 공통): **무기 궤적 스윕(Sweep) 트레이스**.
     * 무기 메쉬에 시작/끝 소켓(WeaponTrace_Start / WeaponTrace_End)을 두고, 몽타주의 판정 구간(ANS_HitWindow) 동안 매 프레임 "이전 프레임 위치 → 현재 프레임 위치"를 캡슐/구체로 스윕.
     * 이유: 부위 절단이 "어느 부위 콜리전을 맞혔는가"에 달려 있어 정확한 궤적 판정이 필요. 프레임 사이 빠른 휘두르기도 놓치지 않음.
     * 한 번의 스윙에서 같은 대상은 1회만 적중 (스윙마다 HitActors 목록 초기화).
     * 보스의 큰 공격(몸통 박치기, 꼬리 휩쓸기 등): 무기 대신 ANS_HitWindow에 박스/구체 모양을 지정한 형태 판정 [제안].
     * 권한: 서버(방장)에서 판정 확정, 공격자 클라이언트는 이펙트/히트스톱만 먼저 표시(예측).
   * 원거리 투사체 (유형 A·B): 투사체 액터의 구체 콜리전 충돌로 판정 (5장 3). 서버에서만 피해 처리.
   * 지면 마법 (유형 C): 발동 순간 마법진 위치에 구체/원기둥 Overlap 1회. 지속 장판은 0.5초 [제안] 간격 틱마다 Overlap.
   * 자신 중심 범위기(범위힐, 도발 등): 시전 순간 SphereOverlap 1회.
15. 가드 판정 규칙:
   * 가드 성공 조건 [확정]: 가드 중 + 공격자가 전방 180°(내적 −0.2 이상). 등 뒤 피격은 가드 실패(피해 100% + 피격 리액션 + 가드 해제).
   * 가드 성공 시 HP 피해 [현재 구현]: 원래 피해 × GuardDamageMultiplier(현재 0.2 = 20%, 무기 공통). 아래 무기별 흡수율 표는 [제안] — 무기 데이터에 흡수율이 생기면 교체.
   * 가드 성공 시 스태미나 소모 [확정 방향]: 공격 등급별 고정값. 약공격(Effect.Hit.Light) 10 / 강공격(Effect.Hit.Heavy) 20 [제안 수치]. (현재 구현은 원래 피해 × 0.5 — 등급별 고정값으로 교체 예정)
   * 가드 관통 3단계 [확정]: 공격마다 아래 중 하나.
| 단계 | 태그(공격자 측) | 가드 성공 시 결과 | 기본 사용처 |
|---|---|---|---|
| 없음 | — | 막음. 피해 감소 + SP 소모, CC(넉다운 등) 미적용 | 일반 약/강 공격 |
| CC 관통 | Damage.GuardPierce | 피해는 가드처럼 감소 + SP 소모, **CC는 그대로 적용**(넘어짐) | 적의 넉다운/CC 공격 기본값. 플레이어 스킬은 "관통 시작 레벨"부터 |
| 가드 불가 | Damage.Unblockable | 가드 자체 무시. 피해 100% + CC 적용. 회피로만 대응 | 보스 일부 패턴 (붉은 섬광 예고) |
   * 공격자 측 태그 부여 방식: 공격 GA의 Activation Owned Tags에 Damage.GuardPierce / Damage.Unblockable 추가 (공격 중에만 유지). [현재 구현: Damage.Unblockable 판정 완료, Damage.GuardPierce는 미구현]
   * 버티는 가드 [확정 방향]: 방어자에게 State.Defense.Steadfast(가칭)가 있으면 CC 관통 공격도 막음(넘어지지 않음). 가드 불가는 여전히 못 막음. 막을 때 SP 추가 소모 [제안: +10].
     * 부여 수단: 디펜더 패시브(상시) 또는 액티브 버프(지속시간 동안) — 스킬 GE의 Granted Tags로 부여.
   * 플레이어 스킬 관통 레벨 [확정 방향]: Skill_Spec / DT_SkillData에 "GuardPierceLevel" 컬럼 추가 (0 = 관통 없음, N = 스킬 레벨 N 이상부터 CC 관통). 현재 몬스터는 가드하지 않으므로 결투(PvP)와 향후 가드 몬스터(방패병 등)에 적용.
   * 참고 공식(무기별 흡수율/안정성 도입 시) [제안]:
     * 가드 성공 시 HP 피해 = 원래 피해 × (1 − 가드 흡수율)
     * 스태미나 소모 = 등급별 기본값 × (1 − 가드 안정성)
   * 가드 흡수율/안정성은 무기(방패) 데이터에 지정. 1차 기준 [제안]:

| 가드 수단 | 물리 흡수율 | 마법 흡수율 | 안정성 |
|---|---|---|---|
| 방패 | 90% | 50% | 높음 (0.5) |
| 대검 | 60% | 20% | 중간 (0.3) |
| 한손 무기 / 단검 | 40% | 10% | 낮음 (0.1) |
| 스태프 / 둔기 | 30% | 40% | 낮음 (0.1) |

   * 스태미나가 0이 되면 가드 브레이크 (State.Groggy 1.5초) — 기존 규칙 유지. [현재 구현: 가드 강제 해제 + State.Groggy/State.Stunned 1.5초(클라이언트 복제). 전용 몽타주(Anim_Guard_Break + Anim_Guard_Break_Stun) 미연결]
16. 패링(저스트 가드) 및 저스트 회피 [확정]:
   * 패링 조건: **방패(Weapon.Type.Shield) 착용** + 정면 피격 + 가드 키 입력 후 **0.2초** 안. 클래스 무관. 방패가 없으면 일반 가드만.
     * 인정 시간은 0.2초 (일반적으로 0.1~0.2초. 멀티플레이 지연을 감안해 넉넉한 쪽 채택). 상수로 조정. 서버 시간 기준으로 시작하고, 빡빡하면 0.25초 또는 클라이언트 예측 + 서버 검증으로 변경.
     * 가드 불가(Unblockable) 공격은 패링도 불가.
     * 연타 방지 [제안]: 패링 실패(인정 시간 안에 피격 없음) 후 약 0.5초 동안은 가드를 다시 눌러도 패링 인정 시간이 열리지 않음 (일반 가드는 됨).
   * 성공 효과: 피해 0 + 스태미나 소모 0 + Event.Parry.Success 발생 (패시브 트리거, 탱커 보너스 어그로). 연출 [확정]: 불꽃 VFX(NS_Parry_Spark) + 사운드는 모든 화면, 카메라 흔들림은 본인만. 히트스톱 없음(멀티), 글자 없음. 적 경직은 전용 ParriedMontage 재생 속도로 조절.
   * 디펜더 패링 패시브 [확정 방향]: 패링 자체는 방패 능력, **추가 효과는 디펜더 패시브(레벨업)** 로만 올림. 예 [제안]: 인정 시간 +0.05 / 0.08 / 0.1초, 반격 피해, 보너스 어그로, 그로기 누적 증가. 기존 Def_P_GuardSuccess와 연결 검토.
   * 스킬창 표시 [제안]: 공통 영역에 패링 아이콘 (방패 미착용 시 회색 + "필요 무기: 방패"). 디펜더 패링 패시브는 우측 패시브 목록.
   * 저스트 회피 [확정]: 회피 무적(ANS_DodgeIFrame, State.IFrame) **시작 후 앞부분 약 0.15초** 안에 공격을 피했을 때만 Event.Dodge.Just. 그 이후 무적 구간에서 피하면 일반 회피 ("DODGE" 글자만).
     * 구현 방향: ANS_DodgeIFrame 시작 시각을 서버에 기록하고 피격 시각과 비교. 저스트 인정 시간은 상수로 조정.
     * 저스트 회피 성공 효과는 클래스별 패시브(레벨업)로 부여 [제안] — 버서커 분노, 어쌔신 확정 치명타, 소서러 마나, 클레릭 소량 회복.
   * 패링당한 적의 반응:
     * 일반몹/엘리트: "패링 경직" 몽타주 재생 (1.0~1.5초 무방비). **몬스터마다가 아니라 스켈레톤(체형)마다 1개**만 제작해 같은 뼈대의 몬스터가 공용 사용. 몽타주가 없는 몬스터는 HitHeavyMontage로 대체.
     * 보스: 경직 몽타주 없이 그로기 게이지 대량 누적. 단, 보스 패턴 중 "패링 가능 표시" 공격만 패링 시 짧은 휘청임 [제안].
   * 데이터 반영: DT_EnemyData에 ParriedMontage, HitResist 컬럼 추가.
17. 스태미나 0 및 아군 피해 [확정]:
   * 스태미나 0(또는 행동 소모량 미만)일 때 **회피(구르기) 불가, 가드 불가**(가드 중이면 가드 브레이크). 평타는 스태미나가 1 이상이면 사용 가능(소모량보다 적어도 실행, 0까지 차감), 0이면 불가 [확정 방향]. 
   * 회복 딜레이 후 자연 회복으로 복귀.
   * 아군 피해 없음: 파티원/다른 플레이어에게 피해·CC·넉백 미적용 (결투 State.Dueling 상대 제외). 힐/버프는 아군에게만 적용.
18. 일반 몬스터 교전 규칙 [확정 + 제안]:
   * 성향 2종 (DT_EnemyData.AggroStyle):
     * 선공형(Preemptive): 시야/감지 범위에 플레이어가 들어오면 먼저 공격.
     * 반응형(Reactive): 공격받기 전까지 공격하지 않음.
   * 반응형 연쇄 반응 [확정]: 반응형 몬스터가 공격받으면 **주변 반경 안의 같은 무리 몬스터도 함께 교전 시작**.
     * 반경 10~15m [제안], 같은 무리 태그(Enemy.Group.<이름>)를 가진 몬스터만 반응 [제안]. 벽 너머는 제외(시야 체크) [제안].
     * 데이터 반영: DT_EnemyData에 AssistRadius, GroupTag 컬럼 추가.
   * 공격 예고: 모든 몬스터 공격은 선딜(Windup) 중 예고 모션 필수 (DT_EnemyData.FirstAttackWindupMin/Max 사용). 강공격·가드 불가 공격은 이펙트로 추가 예고 [제안].
   * 동시 공격 수 제한 [확정 + 제안]:
     * 필드: 한 플레이어와 동시에 교전(근접 거리에서 공격 시도)할 수 있는 몬스터 최대 4~5마리 [확정 방향]. 초과분은 주변을 맴돌며 대기.
     * 공격 토큰 [제안]: 교전 중인 몬스터라도 한 플레이어에게 "동시에 선딜(공격 준비 모션)에 들어가는" 몬스터는 2마리까지. 공격을 마친 몬스터가 토큰을 반납하면 다음 몬스터가 공격. → 4~5마리에 둘러싸여도 예고가 겹치지 않아 회피/가드로 대응 가능.
     * 던전: 교전 수 제한 없음 [확정]. 던전은 고밀도 배치이므로 공격 토큰만 유지할지는 테스트 후 결정 [TBD].
     * 원거리 몬스터는 교전 수와 별도로 계산 [제안].
   * 일반몹 어그로: 보스와 같은 ThreatTable 사용, 단 타겟 변경 임계값 130% [제안] (잔몹이 너무 자주 대상을 바꾸지 않도록).

## 6. 보스 어그로(Threat) 및 탱커 역할
* 기본 규칙:
  1. 전 클래스 피해 1당 어그로 +1.0 (탱커 상시 배율 없음).
  2. 힐 1당 어그로 +0.8~1.0 (실제 회복량 기준).
  3. 받은 피해 1당 어그로 +0.5 [제안] — 탱커가 맞고 버티는 것도 어그로로 인정.
  4. 타겟 변경 임계값: 현재 타겟 대비 110% 초과 시 즉시 변경.
  5. 감쇠: 초당 전체 어그로 5% 자연 감소. 은신(State.Stealth) 시 0 초기화.
* 탱커의 어그로 회수 수단 [확정 방향]:
  * TauntingShout / EarthJudgment: 최상위 어그로 갱신 + 4~5초 강제 고정. 쿨타임 12~15초 [제안].
  * Intercept(가로채기, 신규): 보스가 다른 아군을 향해 공격을 시작하면 그 아군 앞으로 돌진해 대신 막음. 성공 시 대량 어그로 + 3초 고정 [제안].
  * 저스트 패링 / ShieldBash / Neutralize 적중 시 보너스 어그로 + 그로기 게이지 대량 누적.
* 어그로 UI:
  * 보스 HP바 옆에 현재 타겟 표시.
  * 탱커 화면: 타 파티원 어그로가 탱커의 90%를 넘으면 해당 파티원 프레임 점멸 경고.

  * 부활 수단: ① 파티원 부축(옆에서 상호작용 5초 유지, HP 30% 부활 [제안]) ② 클레릭 GoddessBlessing 범위 부활 ③ 제자리 부활 아이템(사망 보호 부적) ④ [부활 지점에서 부활] 버튼 — 유예 중 언제든 선택 가능.
  * 60초 경과 시 자동으로 가장 가까운 부활 지점(웨이포인트 옆 부활석)에서 부활.

## 8. 네트워크, 세션 및 저장 구조
* 최종 구조 [확정 v3.14]: 1~4인 리슨 서버(방장 PC) + 각자 로컬 세이브(추후 Steam 클라우드). 데디케이티드 서버·서버 DB·거래·경매장 없음 (구 Phase 3 삭제).
* Phase 1 (현재 개발 단계):
  * 로비: Standalone. 마을/필드/던전: 리슨 서버(방장 PC). 파티는 마을에서 결성 후 함께 필드로 출발(방장이 세션 개설, 파티원 자동 합류).
* Phase 2 (최종):
  * Steam 또는 EOS 세션/로비 연동 (IP 수동 입력 제거, 친구 초대).
  * 필드 중간 합류(Drop-in): 초대받은 플레이어는 자기 세션을 종료하고 방장 세션에 클라이언트로 접속, 방장 근처 마지막 웨이포인트에서 등장.
  * 방장 이탈 시 파티원은 마을로 복귀.
* 저장 구조 [확정 v3.14, 구현 전 — NON-DIS-2]:
  * SaveGameSubsystem 하나로 저장·로드 (별도 저장 인터페이스 없음).
  * 입장: 클라이언트가 캐릭터 데이터 전체를 구조체 하나(FCharacterSavePayload)로 서버에 보냄 → 서버가 검사(없는 아이템 ID, 레벨 대비 스킬 포인트 총합, 강화 수치 상한, 중복 고유 ID) → 인벤토리 → 장비 → 스탯·스킬 → 퀵슬롯 순서로 한 번에 적용.
  * 저장 시점: 아이템 획득·판매·장비 교체 = 2~3초 모았다가 비동기 저장 / 강화 결과·레벨업·던전 이동 = 즉시 저장 / 게임 종료·캐릭터 선택 = 동기 저장(대기 중인 저장 포함).
  * 파티원 저장: 서버가 확정한 값을 Client RPC로 파티원에게 보내고 파티원 PC가 저장. 방장은 바로 저장.
  * SaveVersion 1 추가 칸: SaveVersion, Gold, SavedMapName(다른 맵이거나 합류 시 저장 좌표 대신 스폰 지점), 아이템별 고유 ID·강화 수치·천장 게이지·인벤토리 칸 번호, 개인 월드 기록(웨이포인트, 처치 보스, 연 상자·비전서, 완료 의뢰, 붉은 달 해금), 덧입기 외형.
  * 안전장치: 작업 전 SaveGames 백업, 직전 세이브 백업 1개 유지, 옛 세이브(버전 0)는 불러올 때 변환(고유 ID 발급 등).
* 지켜야 할 규칙 [확정]:
  1. 모든 아이템 인스턴스에 고유 ID(FGuid) 부여 (중복 아이템 방지, 파티 내 드롭 양도 검증).
  2. 리슨 서버여도 아이템/골드/경험치 변경은 서버 권한(Server RPC)에서만 처리.
  3. 세이브 데이터에 SaveVersion 필드를 두고 버전별 변환 함수 유지.

## 9. 스킬 포인트 성장, 패시브 슬롯, 연계 및 퀵슬롯
* 전 스킬 기본 노출: 모든 클래스 스킬이 스킬창에 노출(초기 핵심기 외 0레벨), 스킬 포인트(레벨업 + 비전서)를 투자해 활성화 및 레벨업.
* 총 스킬 포인트 상한: 만렙 및 전 비전서 수집 시에도 전체 스킬의 약 60~70%만 마스터 가능 → 빌드 선택 강제. 비전투(State.InCombat 아님) 시 골드로 초기화(Respec).
* 패시브 슬롯(4칸): 장착한 패시브만 작동.
* 퀵슬롯(1~0번): 액티브 스킬 배치.
* 스킬창 UI: 단일 대형 창, 중앙 세로 분할. 좌측 액티브 스킬 트리(선행 조건 충족 시 연결선 점등), 우측 패시브 목록.
* 연계 스킬 [확정]:
  * 1단계 스킬 사용 시 Combat.ChainReady 부여 + 2~3초 유예 타이머. 같은 키 재입력 시 2단계 발동, 시간 초과 시 원래 스킬로 복귀.
  * 피격 CC로 스킬이 끊기거나 자원 부족 시 즉시 해제, 퀵슬롯 아이콘 회색 처리.
  * 다음 연계 스킬 아이콘이 캐릭터 옆에 팝업, 해제 시 슬라이드 아웃 (원형 시간 게이지 미표시).
* 회피공격기: 하나의 몽타주에 [회피(초반 0.2~0.3초 무적)] + [카운터 공격]을 연결.
  * 버서커·어쌔신·소서러·클레릭에 1개씩 배치 [확정 방향] (아처 보류). 무적 구간 앞부분에서 피하면 저스트 회피(5장 16) → 카운터 강화 / 보스 그로기 누적.

## 10. 장비, 아이템 및 성장
* 10슬롯 장비 (EEquipmentSlot): 방어구 5(투구, 상의, 하의, 장갑, 신발 — Mutable 연동) + 무기 2(주무기, 보조무기 — 양손 무기 시 보조 자동 해제 및 비활성) + 악세서리 3(목걸이, 귀걸이, 반지 — 메쉬 없음, 스탯 전용).
* 아이템 등급 5단계 [확정]:

|---|---|---|
| Common | 흰색 | 기본 스탯만 |
| Uncommon | 녹색 | 랜덤 옵션 1개 |
| Rare | 파란색 | 옵션 2개 + 소켓 1개 |
| Epic | 보라색 | 세트 효과 대상 |
| Legendary | 주황색 | 고유 효과 1개 (스킬 변형 등) |

  * 툴팁 배경 연출: 등급별 그라데이션/이펙트 (Legendary는 금빛 불꽃/연기 이펙트).
* 아이템 분류: 장비 / 소모품(물약, 버프 비약, 귀환 주문서, 사망 보호 부적) / 재료(강화석, 소켓 해금석, 보석) / 기타·퀘스트(잡템, 열쇠, 입장권).
* 몬스터 전리품 — 개인 루팅 [현재 구현]:
  * 루팅 대상자: 솔로 = 처치자, 파티 = 사망 순간 35m(Party Exp Share Radius) 안의 살아 있는 파티원 (경험치 분배 대상과 동일).
  * 사망 순간 대상자마다 DT_EnemyData → DropList(ItemId, DropChance, MinCount~MaxCount)를 각자 독립 추첨해 저장. 루팅 시 그 결과를 지급.
  * 받을 것이 없는 대상자: 처음부터 루팅 완료 처리 → 그 플레이어 화면에서 외곽선 / 획득하기 팝업 / 상호작용 없음.
  * 비대상자(처치에 관여하지 않은 플레이어): 루팅 불가, 외곽선 없음.
  * 대상자 전원이 루팅(또는 받을 것이 없음)하면 Corpse Life Time After Loot(3초) 뒤 소멸. 남은 루팅이 있으면 Corpse Life Time(120초) 유지.
  * 인벤토리가 가득 차 지급 실패한 아이템은 사라짐 [추후: 우편/바닥 드롭 검토].
* 귀속 규칙: 없음 [확정 v3.14] (거래·경매장이 없으므로). 같은 파티(세션) 안 드롭 양도만 검토. DT_ItemData의 BindType 칸은 사용하지 않음.
* 세트 효과 (DataTable 관리):
  * 방어구: 2세트 최대 HP/MP → 3세트 + 물리 방어/마법 저항 → 5세트 + 공격력 대폭 증가.
  * 악세서리: 2세트 이동속도 + 긴급 회피기 쿨 감소 → 3세트 + 치명타 확률/피해.
* 소켓: 등급에 따라 소켓 존재, 최초 잠김. 대장간에서 골드 + 해금석으로 언락.
  * 붉은 보석: 공격력 / 푸른 보석: 마나 재생·최대 마나 / 녹색 보석: 최대 HP·방어 / 노란 보석: 치명타·쿨감.
* 강화 [확정 2026-11-26, 구현 전]: 대장간 +1 ~ +15. 강화석 + 골드 소모.
  * 스탯: 기본 스탯의 %만큼 증가. 무기는 물리/마법 공격력, 방어구는 물리 방어/마법 저항 기본치에만 적용. 치명타·쿨감 등 보조 옵션은 강화로 오르지 않음.
    * 커브 [제안 수치]: +1~+10 단계당 약 +5%, +11~+15 단계당 약 +8~10% (+15 누적 약 +90~100%).
    * 고정값이 아니라 %인 이유: 낮은 등급 +15가 높은 등급 +0을 넘어서지 않게 (상위 등급 파밍 동기 유지).
  * 성공률 [제안 수치]: +1~+5 100% / +6~+10 70%→40% / +11~+15 30%→10%.
  * 실패: 강화석·골드만 소모. 장비 파괴·단계 하락 없음 (협동 게임에서 파티원 간 격차·이탈 방지).
  * 천장: 실패할 때마다 아이템의 천장 게이지가 차고, 100%면 다음 강화 확정 성공. 성공하면 0. 기준 [제안]: +6~+10 최대 3~5회, +11~+15 최대 6~10회 안에 성공.
  * 데이터: DT_Enhance 한 표 (단계 → 성공률, 실패 시 게이지 증가량, 강화석 수, 골드, 스탯 %). 아이템 데이터(DT_ItemData)에는 강화 칸을 두지 않음.
  * 개별 아이템 값: 강화 수치(UInventoryItem.EnhancementLevel, 이미 있음) + 천장 게이지(추가 필요). 세이브(FInventorySaveData, FEquipmentSaveData)에 둘 다 저장 — 지금은 ItemId·수량만 저장하므로 강화 구현 때 SaveVersion과 함께 추가.
  * 권한: 강화 판정과 재료·골드 차감은 서버(Server_EnhanceItem)에서만.
  * [TBD] 상위 장비로 갈아탈 때 분해 시 강화석 환급 또는 강화 수치 일부 계승.
* 개별 드랍(Personal Loot): 파티원마다 독립 드랍 판정.

## 11. 물약 및 회복 [확정]
* State.InCombat 중 모든 회복 물약 사용 불가. 전투 중 회복은 클래스 자가 회복 스킬과 클레릭 힐로만 가능.
* 비전투 시 물약: 3초 복용 HoT, 이동 시 취소, 쿨타임 30초 [제안].
  * 회복량은 아이템 데이터 Consumable.EffectValue: 1 이하 = 최대 HP 대비 비율(0.3 = 30%), 1 초과 = 고정 회복량. 0이면 기본 30%.
  * 쿨타임은 아이템 데이터 Consumable.CooldownGroupId / CooldownTime (같은 그룹끼리 공유).
* 물약은 상점/드랍으로 수급 (연금술 없음).
* 회복 수단의 역할 분담 [제안]:
  * 전투 중: 클래스 자가 회복 스킬 / 클레릭 힐 (물약 불가).
  * 전투 직후: 물약 = 다음 교전 전에 빠르게 채우는 수단 (3초).
  * HP 자연 회복(GE_HPRegen): 비전투 시에만, 매우 느리게 (예: 2초마다 최대 HP의 1%, 설정법 17.5) — 물약을 아낄지 시간을 쓸지 선택하게 함. 전투 중 자연 회복은 0 [제안].

## 12. 필드 탈것(Mount)
* 1막에 포함 [확정 v3.14]. 버티컬 슬라이스 다음 단계에서 추가.
* 1막 범위: 말 1종(조선 조랑말 느낌), 비전투 전용, 탑승 중 스킬 없음. 질주·도약 하차는 여유가 있을 때 [제안].
* 구현 방식 [제안]: 탈것을 따로 조종하는 폰으로 만들지 않고, 플레이어 캐릭터에 말 메쉬를 붙이고 이동 속도·애니메이션만 바꿈 (지금의 이동·네트워크 코드 재사용).
* 필요한 애니메이션: 말(대기·걷기·달리기·정지) + 타는 사람(탑승·하차·안장 자세).
* 탈것 외형은 스팀 DLC 코스튬 후보 (해태, 백호, 천마 등 설화 탈것).
* 사용 가능 지역: 필드 [확정]. **인스턴스 던전 내부 소환 불가** [확정]. 마을 허브 허용 여부 [TBD]. 던전 입장 시 탑승 중이면 자동 하차.
* 비전투(State.InCombat 아님) 시 이동 중 단축키 입력으로 멈추지 않고 즉시 소환 및 탑승 (State.Mounted, 초속 12~15m).
* 탑승 중 Ability.Mount.Sprint / Ability.Mount.JumpDismount 사용 (1막에서는 여유가 있을 때).
* 잔몹 평타에는 낙마하지 않음. 직접 하차/공격 키 입력 또는 State.CrowdControl.* 유발 공격 피격 시 강제 하차.

## 15. UI / HUD
* 좌상단: 클래스 아이콘, 레벨, 닉네임 + HP/MP/스태미나 3단 바.
* 좌측: 파티원 프레임 (HP/MP, 클래스 아이콘, 버프, 어그로 경고 점멸).
* 상단 중앙: 보스 HP바 + 그로기 게이지 + 현재 타겟 표시.
* 우상단: 미니맵 (북쪽 표시, 내 위치, 적 빨간 점, 목적지 아이콘). M: 전체 지도.
* 하단 중앙: 퀵슬롯 1~0. 최하단: 경험치 바.
* 인벤토리: 단일 50칸 + 상단 필터([전체]/[장비]/[소모품]/[재료]/[기타] — 비해당 아이템 흑백 처리), 자동 정렬(종류 → 등급), 신규 획득 레드닷, 장착 장비와 듀얼 비교 툴팁(증가 초록/감소 빨강).
* UI Z-Order / ESC 스택 규칙 유지.
* 상단 적 정보 HUD (이름 / HP / 거리) [현재 구현]:
  * 조준(크로스헤어 25m)한 살아있는 적이 있으면 그 적을 우선 표시 (비전투 중에도 조준하면 보임).
  * 조준한 적이 없으면 전투 타겟을 표시: 마지막으로 때린 적, 없으면 나를 노리는 적 중 가장 가까운 적.
  * 전투 타겟은 State.InCombat 동안 거리와 관계없이 유지. 전투가 끝나거나(Combat State Duration 후) 대상이 죽으면 사라짐.
* 적 머리 위 HP바 [현재 구현] (BP_Enemy_Base → UI|HPBar → Show HP Bar Only In Combat = true 일 때):
  * 그 적이 나(화면을 보는 플레이어)를 추적 중이면 어그로 시작부터 표시, 어그로가 풀리면 숨김.
  * 내가 적중시키면 5초간 표시 (다른 플레이어를 쫓는 적도).
  * 다른 플레이어만 쫓는 적, 어그로가 풀린 적은 HP가 깎여 있어도 숨김.
  * 적의 추적 대상은 AEnemyCharacter::AggroTarget (서버 BTService_UpdateTarget에서 설정, 클라이언트로 복제).
* 플로팅 숫자 색: WBP_DamageNumber(/Game/Non/UI/Floating)의 OnSetupVisuals 이벤트에서 Category별로 결정 (Heal = 물약·스킬 회복 +N).

### 17.5 설정 절차
#### 물약 수치 지정 (아이템 DataTable)
1. 콘텐츠 브라우저에서 아이템 DataTable(DT_ItemData)을 연다.
2. 물약 행 선택 → Item Type = Consumable 확인.
3. Consumable 펼치기:
   * Effect Value: 총 회복량. 0 < 값 ≤ 1 이면 최대 HP 대비 비율(0.3 = 30%, 1 = 100%), 1 초과면 고정 HP(250 = 250 회복). 0 이면 GA의 Default Total Heal Ratio(30%).
     주의: 1 을 넣으면 1 HP가 아니라 100% 회복.
   * Cooldown Group Id: 쿨타임을 공유할 그룹 이름 (예: Potion_HP). 비우면 쿨타임 없음.
   * Cooldown Time: 쿨타임(초).
4. 저장. 회복량은 복용 시간 동안 틱마다 나눠서 들어간다 (예: 30%, 3초/0.5초 → 6틱 × 5%).
* 예시 등급 [제안]: 소형 0.25 / 중형 0.4 / 대형 0.6, 쿨타임 30초 공통 그룹.

#### 물약 복용 시간·주기를 에디터에서 바꾸기 (GA_ConsumePotion 파생 BP)
1. 콘텐츠 브라우저 /Game/Non/Blueprints/Abilities/GA/Player 에서 우클릭 → Blueprint Class → 부모 클래스 검색 "GA_ConsumePotion" → 이름 GA_ConsumePotion_BP.
2. GA_ConsumePotion_BP 열기 → Class Defaults → Potion: Potion Duration(복용 시간), Potion Tick Interval(회복 주기), Default Total Heal Ratio, Potion Drink Montage, Cooldown Effect Class 설정 → 컴파일·저장.
3. BP_NonCharacterBase → Class Defaults → Default Abilities 배열에 GA_ConsumePotion_BP 추가 → 컴파일·저장.
4. 코드(GiveStartupAbilities)는 Default Abilities에 GA_ConsumePotion 파생 클래스가 있으면 C++ 기본 클래스 대신 그것을 부여한다.
* 틱 수 = 복용 시간 ÷ 회복 주기 (소수점 버림). 회복 숫자(+N)는 틱마다 실제로 찬 양으로 표시.

#### HP 자연 회복을 최대 HP 비율로 바꾸기 (GE_HPRegen)
1. /Game/Non/Blueprints/Abilities/GE/GE_HPRegen 열기.
2. Period: 회복 간격(초). 부드럽게 보이려면 1~2초 권장.
3. Modifiers[0] (Attribute = NonAttributeSet.HP, Modifier Op = Add Base):
   * Magnitude Calculation Type: Scalable Float → Attribute Based 로 변경.
   * Backing Attribute → Attribute To Capture: NonAttributeSet.MaxHP
   * Attribute Source: Target (자기 자신에게 거는 GE라 Source여도 같음)
   * Snapshot: 체크 해제 (레벨업·장비로 최대 HP가 바뀌면 바로 반영)
   * Coefficient: 1회당 비율 (0.01 = 최대 HP의 1%)
4. 컴파일·저장.
* 전부 차는 시간 = Period ÷ Coefficient. 예: 2초 / 0.01 → 200초, 2초 / 0.005 → 400초.
* 권장 [제안]: Period 2초, Coefficient 0.01 (빈 HP → 약 200초). 레벨이 올라도 체감 속도가 같다.
* SP/MP(GE_SPRegen / GE_MPRegen)도 같은 방법으로 MaxSP / MaxMP 비율로 바꿀 수 있다.
